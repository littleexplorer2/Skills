# 独立代码复核与 Computer Use 验收

## 1. 总原则

独立复核用于发现主实现者遗漏，不代替本地测试。所有审查者都只获得完成任务所需的仓库、计划、差异和验证证据；不把预期答案或“应该没有问题”塞进提示。

按 [模型分工](../SKILL.md#模型分工) 选择 Codex 主智能体和子代理，并遵循 [子代理派发与复用](../SKILL.md#子代理派发与复用)。主智能体负责代码修改、解释命令和日志，以及最终判断。

## 2. 代码审查子代理

对实质代码、迁移或算法修改，在相关本地测试通过后交给指定的代码审查子代理：

- 模式：只读，不修改文件；
- 目标：正确仓库中属于本轮的最终增量；提示中同时提供开始时的 git status/diff 基线、已知他人改动和本轮涉及路径，避免把脏工作树全部归因于本任务；
- 输入：用户确认的计划、适用规则、关键不变量、验证结果和明确审查重点；
- 输出：按严重度列出高置信、可操作的缺陷，包含文件/位置、失败场景和原因；无发现明确写 No findings；
- 额外要求：区分实际缺陷、环境限制、数据限制和建议性重构。

审查提示应要求检查：

- 合同/owner/层间调用是否一致，有无第二套逻辑；
- 所有生产者、消费者、调用者、缓存、Worker、存储、导入导出和文档是否同步；
- 边界、单位、身份、特殊分类、unknown 和去重；
- 迁移、备份、失败恢复、并发、隐私和旧数据；
- 算法正确性、评分/排序、剪枝、停止和版本；
- UI 状态、默认值、动态更新、响应式和可访问性；
- 测试是否真正覆盖故障而非只匹配文本。

主智能体逐项核实审查发现，修复代码并重跑相关门禁。每次实质修改后派发最终增量复核，优先续用已完成上轮审查的子代理。

finding 若只是实现缺陷就修复；若揭示的是新的产品语义、数据迁移或范围选择，立即在处理该 finding 前提出结构化选择题。不得替用户选择后再把该 finding 当作已关闭。

## 3. 浏览器子代理调试与验收

Computer Use、浏览器调试及 UI 功能验收交给指定的浏览器子代理。需要检查本地应用时，等待最新构建和服务可用后再派发：

- 工具：Computer Use；
- 模式：只检查，不修改代码或数据文件；
- 明确目标：工作副本、URL、端口、页面、测试身份/数据、viewport 和要完成的用户流程；
- 浏览器调试时，复现指定问题并记录操作步骤及相关的 DOM/AX、控制台、网络或截图证据；
- 要求同时看可见页面和可访问状态，验证值、勾选、disabled、错误、结果和动态变化；
- 要求说明实际观察到的证据；无法连接浏览器、tab、窗口或服务时精确列出未验证范围，不得推测通过。

打开页面前先建立数据隔离：使用独立浏览器 profile、临时存储命名空间、可丢弃测试账户/数据库或项目规定的等价机制。先判断页面加载是否会自动迁移、写回或清理私人旧数据；无法隔离时停止并请求授权，不用真实私人状态做破坏性验收。“只读验收”是指不修改代码、原始/真实用户数据和生产状态；允许在明确的隔离测试状态中执行设置、保存、刷新、恢复和迁移流程。

UI 验收至少覆盖：

- 新用户是否能不看教程找到设置并完成主流程；
- 多页面是否读取同一设置，切换后是否同步；
- 默认值、空选择、未知/待核、错误和无结果；
- 目标/上限、硬/软、实际/计划等易混概念是否可辨；
- 结果排序、解释、预览与应用是否一致；
- 窄屏、桌面、滚动、折叠、字体、卡片、溢出和操作命中；
- 修改输入后动态计算是否正确且不卡顿。

## 4. Computer Use 操作纪律

浏览器子代理使用 Computer Use 时：

1. 完整读取当前 computer-use 技能和工具文档；
2. 选择用户指定浏览器/窗口，或在未指定时选择可用目标；
3. 首先确认 URL、页面标题和版本，避免旧端口/测试版；
4. 操作后读取最新 AX/DOM；视觉问题再取截图；
5. 优先语义 locator/AX 操作，坐标只用于没有稳定语义目标的场景；
6. 输入本地测试数据不等于生产写入；外部发送、权限、删除或其它 consequential action 仍遵守确认规则；
7. 响应式任务用 viewport 能力设置精确尺寸，结束前恢复；
8. 观察到最终结果后按工具要求提交一次 completion summary，再使用其它工具或回复；
9. 不为绕过工具隔离改用未授权 GUI 技术。

若浏览器子代理因隔离无法访问主智能体的 IAB：

- 让浏览器子代理检查可用浏览器和 tab，并按精确 URL 重试一次。
- 仍无法访问时记录浏览器调试和验收的未验证范围。主智能体继续收集可获得的本地测试证据。

必需的浏览器验收仍受阻时，按选择题门确认重试、接受具体替代证据或调整验收范围，并在交付中报告实际结果。

## 5. 审查与验收顺序

推荐：

1. 本地定向与完整验证；
2. 代码审查子代理初审；
3. 主智能体核实发现并修复代码；
4. 主智能体运行相关回归，代码审查子代理复核最终增量；
5. 构建并启动正确版本；
6. 浏览器子代理调试或验收 UI；
7. 主智能体核实浏览器证据、修复代码并重建，浏览器子代理重跑 smoke 和可视检查；
8. 停止临时服务，最终状态和 diff 检查；
9. 交付。

代码审查与视觉验收可在互不写文件时并行，但不要让二者同时修改共享工作树。

## 6. 可复用提示

完整提示模板见 [06-templates.md](06-templates.md)。提示中必须包含“仅审查，不修改”“目标是哪个工作副本”“最终差异”“无发现时明确 No findings”或“无法观察时明确未验证”，避免模糊委派。
